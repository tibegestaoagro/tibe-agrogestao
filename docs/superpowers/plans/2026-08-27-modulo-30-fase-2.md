# Módulo 30, fase 2: plano de implementação

> **Para executores:** use `superpowers:subagent-driven-development` ou
> `superpowers:executing-plans` para executar tarefa por tarefa. Os passos usam
> caixa (`- [ ]`) para acompanhamento.

**Objetivo:** o rebanho passa a separar propriedade de localização, com os cinco
fluxos de estadia temporária e os cinco números que o cliente pediu.

**Arquitetura:** um model `HerdStay` guarda a identidade e os atributos do
episódio; as movimentações apontam para ele por `stay_id`, e o saldo continua
sendo a soma delas. Duas rotas (abrir e encerrar) servem os cinco fluxos, que
diferem por uma tabela de validação, não por código duplicado.

**Stack:** Prisma 7 sobre PostgreSQL 17, Next.js 14 (App Router), Zod nas rotas,
suítes em `tsx scripts/*.test.ts`.

**Spec:** [2026-08-27-modulo-30-fase-2-design.md](../specs/2026-08-27-modulo-30-fase-2-design.md)

## Restrições globais

- **O saldo nunca é gravado** (invariante 2). `HerdStay` não tem campo de
  quantidade nem de "encerrada": os dois são derivados das movimentações.
- **`tenant_id` nunca vem do client** (invariante 1). Toda query usa o client
  escopado; `HerdStay` entra em `TENANT_SCOPED_MODELS`.
- **Migração antes do push** (invariante 3), aplicada primeiro no Docker local.
- **Regra de negócio em `src/lib/actions/`**, nunca no route handler.
- **Travessão (U+2014) é proibido**; heredoc com escape no shell também.
- **Cor crua do Tailwind é reprovada** pelo `npm run check` desde a frente 1:
  a tela nova usa token semântico e o kit (`FormSheet`, `Field`, `EmptyState`).
- **`npx tsc --noEmit` tem ruído pré-existente** em
  `scripts/m23-token-auth.test.ts`, e só nele. Erro em outro arquivo é seu.
- **Banco local, sempre:**
  `DATABASE_URL="postgresql://tibe:tibe@127.0.0.1:55432/tibe_dev?schema=public"`
  antes do comando, com `docker start tibe-pg` antes de tudo.

- [ ] **Passo 2: acrescentar os tipos de movimento**

No `enum HerdMovementType`, depois de `ajuste`:

```prisma
  envio_pasto_terceiro
  envio_boitel
  retorno_estadia
  entrada_terceiro
  saida_terceiro
  desaparecimento
```

Um `retorno_estadia` só para os três casos de volta: a situação de origem já
diz de onde o animal está voltando. Morte confirmada de um desaparecido reusa
o `morte` que já existe, com origem em `desaparecido`.

- [ ] **Passo 3: declarar o model**

```prisma
/// Uma estadia: as cabeças estão fora do normal, temporariamente, e isso
/// termina. Ver docs/superpowers/specs/2026-08-27-modulo-30-fase-2-design.md.
///
/// NÃO tem quantidade nem situação de encerrada, e isso é deliberado. A
/// quantidade é a soma das movimentações que apontam para cá (invariante 2), e
/// a estadia está aberta enquanto esse saldo for maior que zero. Campo gravado
/// e realidade divergem em silêncio: é a decisão 9 do Módulo 31.
model HerdStay {
  id          String       @id @default(cuid())
  tenant_id   String
  type        HerdStayType
  property_id String

  /// Dono do pasto, nome do boitel, dono dos animais de terceiros. Nulo no
  /// desaparecimento, que não tem contraparte.
  counterparty_name String?
  location_name     String?
  city              String?

  /// Saída, entrada, ou o dia em que o sumiço foi percebido.
  started_at      DateTime
  expected_end_at DateTime?

  charge_type  HerdChargeType?
  charge_value Decimal?        @db.Decimal(14, 2)

  /// Motivo provável, que o §4 do complemento pede no desaparecimento.
  reason String?
  notes  String?

  recorded_by_user_id String?

  canceled_at         DateTime?
  canceled_reason     String?
  canceled_by_user_id String?

  created_at DateTime @default(now())

  tenant    Tenant         @relation(fields: [tenant_id], references: [id], onDelete: Cascade)
  property  Property       @relation(fields: [property_id], references: [id], onDelete: Cascade)
  movements HerdMovement[]

  @@index([tenant_id, type])
  @@index([tenant_id, started_at])
}
```

E em `HerdMovement`, junto de `negotiation_id`:

```prisma
  /// Estadia que originou o movimento. Nulo em tudo que não é estadia.
  stay_id String?
  stay    HerdStay? @relation(fields: [stay_id], references: [id], onDelete: SetNull)
```

`closeStay`, numa transação só:

1. lê a estadia e o saldo aberto dela (soma das movimentações com aquele
   `stay_id`, entradas menos saídas);
2. **recusa quando `vendidos + retornados + outros` não é igual ao saldo
   aberto**, com `DESTINOS_NAO_BATEM` e `field: "quantity"`;

4. grava uma movimentação por destino, todas com o mesmo `stay_id`: vendidos

   retornados voltam por `retorno_estadia`, outros saem pelo tipo que a tabela
   define;
5. se houver `value`, cria a receita dos vendidos por `createLinkedEntry`.

⚠️ **"Encerramento parcial" no documento não é "informar menos que o total".**
É informar todos os destinos, sendo que um deles é "seguiram para outro
destino". A soma **sempre** fecha; o que varia é para onde foram. Ler isso
errado produziria uma estadia que nunca zera.
